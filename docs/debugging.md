# VSCodeデバッグ用語集

VSCodeでPythonのテストやコードをデバッグするときに出てくる用語と、それぞれをどんな場面で使うかをまとめます。

## 1. 基本操作一覧

| 用語 | 主なショートカット | 意味 |
|---|---|---|
| ブレークポイント (Breakpoint) | 行番号の左をクリック | そこでプログラムの実行を一時停止させる目印 |
| 続行 (Continue) | F5 | 次のブレークポイントに当たるまで、あるいはプログラム終了まで実行を再開する |
| ステップオーバー (Step Over) | F10 | 現在の行を実行して次の行へ進む。その行の中で関数が呼ばれていても、内部には入らず1行として扱う |
| ステップイン (Step Into) | F11 | 現在の行で呼ばれている関数の**内部**に入り、その関数の1行目で止まる |
| ステップアウト (Step Out) | Shift+F11 | 今いる関数の残りを実行しきって、呼び出し元の続きに戻る |
| 再起動 (Restart) | Ctrl+Shift+F5 | 今のデバッグセッションを終了し、最初からデバッグをやり直す |
| 停止 (Stop) | Shift+F5 | デバッグセッションを終了する |

## 2. 使い分けの目安

### ブレークポイント

「ここで一度止めて変数の中身を見たい」という行に置きます。
このプロジェクトの例では、`lambda_function.py` の `obj = s3.get_object(...)` の行に置くと、
`lambda_handler` が呼ばれるたびに（＝テストが実行されるたびに）そこで止まります。

複数のテストから同じ関数が呼ばれる場合、ブレークポイントは**呼ばれた回数だけヒットする**点に注意してください。
（詳細は [`tests/README.md` の「5. ブレークポイントで except に入らないように見えるとき」](../tests/README.md) を参照）

### 続行（Continue）

今止まっている場所から、次のブレークポイントまで一気に進めたいときに使います。
例えば複数テストをまとめてデバッグしていて、1回目のヒット（200ケース）を確認し終わったら
Continueで2回目のヒット（500ケース）まで進める、という使い方をします。

### ステップオーバー（Step Over）

「今の行が何をしたかだけ知りたい。呼び出し先の中身までは追わなくていい」ときに使います。
基本の移動手段はこれで、`assert` 文の結果を1行ずつ確認していくような場面に向いています。

### ステップイン（Step Into）

「呼び出し先の関数の中で何が起きているか追いたい」ときに使います。
このプロジェクトでは `s3.get_object(...)` の行でステップインすると、`unittest/mock.py` という
ライブラリ内部のコードに入ってしまい、追いたい `lambda_function.py` のロジックから外れてしまいます。
自分が書いたコード以外の内部実装を追いたいとき以外は、基本はステップオーバーを使うほうが分かりやすいです。

### ステップアウト（Step Out）

ステップインで関数の中に入ったものの、「もう中身は分かったので呼び出し元に戻りたい」ときに使います。
例えば誤って `unittest/mock.py` の中にステップインしてしまった場合、ステップアウトを数回使うことで
`lambda_function.py` 側に戻ってこられます。

### 再起動（Restart）

「ブレークポイントの位置を変えたい」「最初からもう一度追いかけ直したい」ときに使います。
デバッグを停止してから再度実行するのと同じ結果になりますが、1操作でまとめて行えます。

### 停止（Stop）

デバッグで確認したいことが終わったら、セッションを終了します。
止めずに次のデバッグを開始しようとすると、古いセッションが残ったまま分かりづらくなることがあるので、
区切りが付いたら都度止める習慣をつけると安全です。

## 3. 具体例：`test_returns_500_when_connection_fails` を追う

1. `lambda_function.py` の `obj = s3.get_object(...)` の行にブレークポイントを置く
2. Test Explorer で `test_returns_500_when_connection_fails` を右クリック →「Debug Test」
3. ブレークポイントで停止したら、ステップオーバー（F10）でその行を実行する
4. `get_object()` はモックの `side_effect` により例外を送出するため、次に止まるのは
   `except Exception as e:` の行になる
5. 変数 `e` の中身（`str(e) == "connection timeout"`）を確認したら、続行（F5）かステップオーバーで
   テストの終わりまで進める
